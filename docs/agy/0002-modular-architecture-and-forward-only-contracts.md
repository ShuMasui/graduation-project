# 2. ステップ独立モジュール設計と順方向単方向DTO契約の採用

* **ステータス**: 承認済 (Accepted)
* **決定日**: 2026-08-25
* **文脈**: 再現実験プログラム (`exp-reproduce/`) のモジュール構造とインターフェース設計

---

## 1. 背景と課題 (Context & Problem Statement)

EEG 解析パイプライン（BEM構築、アトラス変換、順モデル、前処理、ノイズ共分散、音源推定、領域集約、統計検定）は各ステップの処理が長く、1 つのスクリプトにまとめるとコードが肥大化し、単体テストやデバッグが困難になります。一方で、無秩序にモジュール分割すると相互参照や循環依存が生じる懸念がありました。

---

## 2. 決定事項 (Decision Outcome)

以下のモジュール設計規約およびデータ契約ルールを採用しました。

### 2.1 4ファイル分離規約 (Standard Module Layout)
各フローステップを独立したサブディレクトリとして切り出し、以下の4ファイルで構成する。
- **`types.py`**: モジュール内部で完結する設定パラメータや内部データ構造。
- **`output.py`**: 後段のステップへ受け渡す公開出力データ型（`@dataclass(frozen=True)` の DTO）のみを定義。
- **`main.py`**: コア処理ロジックとエントリー関数 `run_*` のみを記述。
- **`test_main.py`**: Python 標準の `unittest` による単体テストコード。

### 2.2 順方向単方向依存ルール (Forward-Only Dependency)
- 各モジュールは **「直前（上流）ステップの `output.py`」のみをインポート可能** とする。
- 兄弟モジュールの内部ロジック（`main.py`, `types.py`）や後段モジュールの参照は一切禁止する。

```text
Step N の main.py  --->  Step (N-1) の output.py (型参照のみ許可)
                      x   Step (N-1) の main.py / types.py (参照禁止)
                      x   Step (N+1) の 全ファイル (逆方向参照禁止)
```

---

## 3. 影響と評価 (Consequences)

### メリット (Pros)
- モジュール間の結合度が極限まで下がり、サブエージェント等による完全並行開発・単体テストが可能となった。
- `@dataclass(frozen=True)` により、パイプライン実行中の意図せぬ副作用（破壊的変更）を防止できた。
- モックデータを用いた単体テスト（`unittest`）が外部リソースなしでミリ秒単位で高速動作する。

### デメリット・留意点 (Cons)
- 各モジュールで `output.py` の定義が必須となるため、軽微なデータでも DTO クラスを作成するオーバーヘッドがある。
